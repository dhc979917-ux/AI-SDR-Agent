# 实现与设计对应

更新：2026-10-20。当前设计书已从实施前方案改为实现同步版；本文用于快速定位代码和能力边界。

| 能力 | 实现位置 | 当前行为与边界 |
|---|---|---|
| 分析编排 | `sdr/engine.py` | 分段 → 抽取 → 校验 → 名称记录 → 评分 → 审核与导出 |
| 名称记录 | `sdr/entities.py` | 优先 raw_company，否则 brand_name；未捕捉则留空，支持人工填写 |
| 企业检索 | 保留的企业目录与 HTTP 适配器 | 不在新分析主链路中；MCP 仅完成本地连接验证 |
| 评分 | `sdr/scoring.py` | intent-3.1；单一分数；高意向有需求与推进条件；0–5 分异常 |
| 证据约束 | `sdr/validation.py`、`prompts/` | 客户角色、逐字引用、字段口径、否定及条件句检查 |
| 录音处理 | `sdr/audio.py`、`audio_processing.py` | 最大 200 MiB、60 分钟；标准化、分片、顺序合并和重试 |
| 角色确认 | `sdr/audio_roles.py`、`static/audio-roles.js` | 原文覆盖检查、自动其他、逐条确认；保护已有确认稿 |
| 个人模型 | `sdr/model_settings.py`、`model_transport.py` | 语音／文字分别配置；员工独立密钥，服务端加密 |
| 审核事务 | `sdr/review.py`、`store.py` | 原始与修订结果分开；版本检查；高影响变更独立复核 |
| 批量审核 | `sdr/review.py` | 无固定业务条数上限，5 分钟预览，一条失败整批回滚 |
| 客户管理 | `sdr/workspace.py`、`static/team.js` | 按归属隔离、管理员调配；客户删改检查修订与关联资料 |
| 分析删除 | `sdr/store.py`、`app.py` | 删除分析及审核反馈，保留客户和原始录音 |
| 导出 | `sdr/app.py` | 候选与正式区分；新名称不要求工商核验，旧 verified 保留来源检查 |
| 反馈 | `sdr/review.py` | 独立验证、发布、撤回；不自动训练或修改 Prompt |

## 状态与持久化

分析执行采用单进程线程池，状态及阶段保存在 SQLite；未完成分析在重启时标记中断，重新分析创建新任务。录音分片可重试，不代表文本分析支持所有节点自动续跑。

写操作重新检查当前权限和修订号。数据库分别保存 `original`、`result`、审核事件和反馈，人工填写不冒充原文事实。历史结果不自动更新到新规则。

## 当前规则对早期方案的替代

企业名称直取替代默认工商候选检索；确定分数替代未知分数区间；账号、个人模型、长录音与客户调配已经落地；单条／批量审核理由选填。单独填写企业名称不要求来源或双人复核，其他事实修正和异常意向仍须遵守证据及复核规则。

历史企业别名可保留管理与适配能力，但当前名称链路不依赖召回，不能声称反馈会自动改善新分析的工商匹配。历史截图和模型报告以各自生成时状态解释。

## 尚未实现

电话挂断自动同步、正式 CRM 写入、真实录音独立盲测、完整音频证据定位、收听时长验证、专用审核员角色、SSO、多租户、分布式持久队列和自动备份均不在当前交付中。部署与厂商接入需要独立验证，不能由接口契约测试推导为真实服务已联调。
